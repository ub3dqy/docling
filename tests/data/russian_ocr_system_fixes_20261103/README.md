# Исправление системных ошибок русского распознавания

Исправления относятся к выбору повторных чтений, передаче уточнённого текста
в таблицы, сохранению неразмещённого текста и геометрии столбцов.
Веса нейросетей, зависимости, прежние ответы и проверяющая программа сохранены.

Итоги и оставшиеся ошибки описаны в [отчёте](REPORT.md).

## Что сохраняется

- `c-before.json`: первоначальные оценки прежнего комплекта C.
- `c-rejected-v4.json`: первый полный повтор, в котором выявлены ухудшения.
- `c-rejected-v7.json`, `c-milestone-v8.json`: последующие полные повторы C;
  после них проверки прежних групп ещё выявляли ошибки.
- `c-after.json`: полный повтор C с окончательной программой.
- `d-first.json`: первый прогон новой группы D после проверок прежних документов.
- `latest-b.json`, `newest.json`, `unseen.json`, `previous.json`: четыре прежние
  группы целиком. Ранее принятые уточнения источников отмечены отдельно;
  первоначальные оценки также сохранены в `original_reference_scores`.
- `field-preservation.json`: прохождение тех же 60 полей C из чтения в выгрузку.
- `punctuation-evidence.json`, `synthetic-rejected-v16.json`,
  `synthetic-rejected-v17.json`: наблюдавшиеся чтения, неудачные проверки
  конечной точки и восстановленный заголовок без изменения контрольного ответа.
- `faint-column-evidence.json`, `faint-column-replay-evidence.json`,
  `faint-column-rejected-v18.json`: потеря и восстановление отдельного столбца
  примечаний. Исходная проверка сумм этого дефекта не замечала.
- `token-order-evidence.json`: одинаковые входные слова и строки, перестановка
  уточнённого фрагмента и восстановленный порядок текста в ячейке.
- `frozen-inputs.json`, `task-start.json`: контрольные суммы программы, моделей,
  прежних образцов и проверяющих программ.
- `*-verification.json`, `pre-d-gate.json`: полнота прогонов, сохранность данных
  и сравнение с прежними результатами до первого запуска D.
- `frozen-runs.json`: одинаковые контрольные суммы программы во всех окончательных
  прогонах. В старых таблицах отдельно сравниваются число строк и столбцов.
- `synthetic-result.json`: отдельная проверка восьми искусственных примеров.
- `attempts.json`, `artifact-hashes.json`: неудачные и прерванные попытки,
  контрольные суммы подробных местных результатов.
- `previous-source-inventory.json`, `d-source-preflight.json`: прежние исходники
  и проверка отсутствия повторов среди девяти новых оригиналов D.
- `sideways-rejected-v11.json`, `sideways-after.json`, `sideways-source-evidence.json`:
  ухудшение и восстановление повёрнутой таблицы при одинаковых строках чтения.
- `open-grid-boundary-proof.json`: проверка незамкнутой наклонной сетки до и после
  исправления; прежний код подтверждён контрольной суммой.
- `assembly-evidence.json`: сохранение подписей чека и связи НДС с суммой.
- `d-stage-evidence.json`: наблюдение этапов после первого прогона D на заключении
  и двух чеках. Программа и первые результаты сохранены; это разбор уже открытой
  группы, а не новая независимая оценка.

В файлах оценок сохранены все исходные проверки текста, строк и полей.
Полные таблицы с непроверяемыми ячейками и выгрузки документов остаются в `output`;
их контрольные суммы записаны. Значения оценок не исправляются вручную.

## Повторение

Оригиналы должны совпадать с `sources.json` соответствующего комплекта.
Модели должны находиться в `model_artifacts/ru`. Команды выполняются из корня проекта
последовательно. Для каждого повторения укажите новую папку результата.

```powershell
uv run --no-sync python -c 'from pathlib import Path; import scripts.qualify_real_russian_ocr as q; q.FIXTURES=Path("tests/data/russian_ocr_holdout_20261102c").resolve(); q.main()' --sources output/russian-ocr-holdout-2026-11-02c/sources --artifacts-path model_artifacts/ru --output output/system-fixes-repeat/c

uv run --no-sync python -c 'from pathlib import Path; import scripts.qualify_real_russian_ocr as q; q.FIXTURES=Path("tests/data/russian_ocr_holdout_20261102d").resolve(); q.main()' --sources output/russian-ocr-holdout-2026-11-02d/sources --artifacts-path model_artifacts/ru --output output/system-fixes-repeat/d
```

Прежние четыре группы повторяются той же проверяющей программой:

| Образцы в `tests/data` | Исходники в `output` | Дополнение к команде |
| --- | --- | --- |
| `russian_ocr_holdout_20261102b` | `russian-ocr-holdout-2026-11-02b/sources` | `--use-source-review` |
| `russian_ocr_holdout_20261102` | `russian-ocr-holdout-2026-11-02/sources` | без дополнения |
| `russian_ocr_unseen` | `real-russian-ocr-new-2026-11-01/sources` | `--use-source-review` |
| `russian_ocr_real` | `real-russian-ocr-2026-11-01/sources` | `--use-source-review` |

Ограничение остаётся прежним: 180 секунд на документ, CPU с четырьмя потоками,
без сетевых соединений Python при распознавании. Непрохождение условий качества
даёт ненулевой код завершения и сохраняется в отчёте.

## Как читать оценки

Прохождение случая требует выполнения всех его условий одновременно.
Доля прошедших случаев не равна доле правильно распознанных букв.
Табличное значение должно находиться в нужной строке и столбце. Поле чека
проверяется в заданной области чтения и по наличию числа в выгрузке. Проверка
наличия числа не доказывает правильность всех связей между полями документа.
Текст сравнивается без исправления похожих русских и латинских букв.

C и четыре прежние группы использованы для разработки. Только первый прогон D
является новой проверкой этой работы. Его ответы зафиксированы до распознавания;
он не используется для подбора исправлений. Группа мала и содержит сходные бланки.
Даже полное прохождение её условий не доказывает точность на любых документах.
