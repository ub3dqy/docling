# Русский текст в PDF и изображениях

В этом форке есть готовая настройка `--ocr-profile ru` для печатных сканов.
Она работает локально на Windows и не требует видеокарты или платного сервиса.
Поддерживаются PDF, PNG, JPEG и TIFF. Рукописный текст здесь не проверялся.

## Установка в этом проекте

Выполните команды из папки проекта. Нужен Python 3.11 или новее.
Настройка `russian` относится к этому форку, а не к пакету из общего примера
`pip install docling`.

```powershell
uv sync --frozen --extra russian --all-packages --no-default-groups
uv run --no-sync docling-tools models download layout tableformer rapidocr russian_ocr_refinement --rapidocr-backend-lang onnxruntime:iso:ru --output-dir model_artifacts/ru
```

Первая загрузка моделей требует интернета. После неё распознавание использует
файлы из `model_artifacts/ru`. Данные документов не отправляются на внешний сервис.

## Распознавание

```powershell
uv run --no-sync docling "скан.pdf" --ocr-profile ru --artifacts-path model_artifacts/ru --device cpu --to md --to text --to json --output output/recognized --fail-on partial
uv run --no-sync docling "фото.jpg" --ocr-profile ru --artifacts-path model_artifacts/ru --device cpu --to md --to text --to json --output output/recognized --fail-on partial
```

Результат сохраняется в `output/recognized`: обычный текст, текст с таблицами
и подробное представление документа. Команда завершится с ошибкой, если часть
документа не обработана. Проверяйте результат перед использованием важных чисел.

Настройка распознаёт всю страницу. Она также заменяет текст, который уже есть
в PDF. Чтобы сохранить обычную обработку готового текста PDF, добавьте
`--ocr-mode default`.

Используется русская модель RapidOCR PP-OCRv5 (`eslav`) через ONNX Runtime.
PDF распознаётся при 300 точках на дюйм, изображения — при 144.
Повторное чтение в другом размере помогает вернуть пропущенные строки.
Сомнительные строки изображений и числа в таблицах дополнительно читаются
отдельно. Для этого используются независимые модели RapidOCR, Tesseract
и локальный русский словарь. Очистка линий таблицы и защитного фона помогает
различать мелкие буквы и цифры. Словарь выбирает среди реально прочитанных
вариантов и не придумывает слова. Расчёты итогов и НДС для замены чисел не используются.
Для знаков перед суммой сохраняется край строки, который обычная обрезка
по буквам могла отсечь. Знак `=` проверяется по изображению и уверенности
отдельного символа в двух чтениях. Исправление знаков не меняет уже прочитанное
число и десятичные разряды. Лишние точки и отдельные подчёркивания в заголовках
исправляются только при согласии разных распознавателей на том же тексте.
Сокращения, окончания предложений, имена файлов, проценты и операторы защищены.
Близкие части одной строки соединяются в порядке чтения. Координаты отдельных
слов сохраняются для распределения текста по ячейкам таблицы.
Чёткая сетка таблицы имеет приоритет перед ошибочно объединёнными строками.
Повёрнутый финансовый бланк дополнительно читается в правильном направлении.
Сетка и числа обрабатываются в этом направлении, а координаты возвращаются
на исходную страницу. Для открытого левого края нужны повторяющиеся линии
и названия строк; недостающие границы не добавляются по известному шаблону.
В числовых столбцах прочерк восстанавливается только по видимому знаку
внутри ячейки. Короткие коды читаются буквально, без дополнения нулями.
Для фотографии с двумя столбцами также проверяются разделитель и порядок строк;
при внутреннем пропуске строки такая попытка отклоняется.
Второй локальный поиск строк на фотографиях помогает найти мелкую цену и разъединить
ошибочно склеенные строки чека. Он использует уже загруженную модель
`PP-OCRv6_det_small.onnx` при включённом повторном чтении в другом размере
и не заменяет явно заданный пользователем поиск строк.
Замена совпадающих строк защищает прочитанные числа, минусы и десятичные разряды.
Пропущенная точка в сумме чека проверяется по изображению и нескольким чтениям;
исходные цифры сохраняются. Подпись итога или НДС соединяется с суммой справа
только при совпадении положения строк. Это сохраняет их связь в обычном тексте.
Для определения чека достаточно нескольких разных печатных полей. При этом
учитывается сходство латинских и русских букв; само распознанное слово этой
проверкой не заменяется. Итоги и НДС проверяются дополнительно даже при высокой
уверенности модели. Уверенно прочитанные цифры при проверке знаков сохраняются.
Текст документа, ошибочно помещённый внутрь изображения, доступен в обычной выгрузке.
Явно заданные язык, режим и другие параметры имеют приоритет над настройкой.
Параметр `scale` задаёт размер для PDF, `image_scale` — для изображений.
Повторное чтение можно отключить через `--ocr-option use_multiscale=false`.
Дополнительное чтение участков отключается через
`--ocr-option use_region_refinement=false`. Для него нужны обновлённая установка
`russian` и модели `russian_ocr_refinement`; старой загрузки одной модели RapidOCR
недостаточно. Файлы Tesseract проверяются по контрольным суммам до распознавания.
Чтение таблиц по линиям отключается через
`--table-structure-option prefer_ocr_grid=false`; `--no-tables` отключает таблицы полностью.

## Проверка на тестовых сканах

В `tests/data/russian_ocr` лежат четыре искусственных скана с известным текстом:
русские буквы и числа, русский с английским, таблица и страница с наклоном 2°,
сниженным контрастом, небольшим размытием и сжатием JPEG. Из них также собран
PDF на четыре страницы. В PDF нет готового текстового слоя.

Проверка обрабатывает каждый скан отдельно и внутри PDF — всего восемь страниц.
Она сверяет исходные файлы по контрольным суммам, сравнивает текст с образцом
и требует точного совпадения всех ячеек таблицы, включая пустые. Во время
распознавания запрещены сетевые подключения из Python. Сетевой трафик нативных
библиотек отдельно не перехватывается.

```powershell
uv run --no-sync python scripts/qualify_russian_ocr.py --artifacts-path model_artifacts/ru --output output/russian-ocr-check
```

Укажите новую или пустую папку для результата. Там появятся распознанные документы
и `qualification.json`: ошибки, время обработки, версии и контрольные суммы
моделей. При непрохождении проверки команда вернёт ошибку.

Повторная проверка на Windows 1 ноября 2026 года прошла для всех восьми страниц
с прежними допустимыми границами:

| Скан | Ошибки в изображении | Ошибки в PDF | Таблица |
|---|---:|---:|---|
| Русский текст | 0,63% | 1,89% | — |
| Русский и английский | 0,70% | 1,39% | — |
| Таблица | 0% | 0% | Все ячейки совпали |
| Наклон и ухудшение изображения | 3,14% | 3,14% | — |

Сравнение не учитывает регистр и повторяющиеся пробелы. Различия между `ё` и `е`,
кириллицей и похожими латинскими буквами, а также знаки препинания считаются
ошибками. Допустимые границы заданы в `expected.json` до запуска распознавания.
Эти результаты относятся только к приложенным искусственным печатным сканам.
Проверка настоящих документов описана ниже. Эти небольшие выборки не дают общей
гарантии точности для других документов.

Для запуска той же проверки через набор тестов установите зависимости разработки:

```powershell
uv sync --frozen --extra russian --all-packages --group dev --no-group docs --no-group examples
$env:DOCLING_TEST_RUSSIAN_ARTIFACTS = (Resolve-Path model_artifacts/ru).Path
uv run --no-sync pytest tests/test_e2e_russian_ocr.py -q
```

Образцы можно создать заново в другой пустой папке. Используйте шрифты с русскими
буквами. Скрипт не распространяет файлы шрифтов и не перезаписывает образцы:

```powershell
uv run scripts/generate_russian_ocr_samples.py --output-dir output/new-russian-scans --font C:/Windows/Fonts/arial.ttf --bold-font C:/Windows/Fonts/arialbd.ttf
```

## Проверка настоящих документов

В `tests/data/russian_ocr_real` сохранены неизменённые образцы для сравнения:
шесть страниц двух опубликованных отчётов, две цветные фотографии документов
и два изображения кассовых чеков. Проверяются 101 число в финансовых таблицах,
16 пар «предмет — оценка», 12 числовых полей чеков и пять участков текста.
Это те же документы и участки, на которых обнаружены ошибки. Они использованы
при исправлениях и не являются независимой новой выборкой.

Ссылки, размеры файлов и их контрольные суммы находятся в `sources.json`.
Сами исходные PDF и фотографии в репозиторий не включены. Локальные копии
предыдущей проверки находятся в `output/real-russian-ocr-2026-11-01/sources`.

```powershell
uv run --no-sync python -m scripts.qualify_real_russian_ocr --sources output/real-russian-ocr-2026-11-01/sources --artifacts-path model_artifacts/ru --output output/real-russian-check/results --use-source-review
```

Для повторного запуска укажите новую или пустую папку. Проверка сначала сверит
исходные файлы и образцы по контрольным суммам. Она сохранит текст, таблицы,
распознанные строки, версии, параметры и контрольные суммы кода.
Код возврата `1` означает, что хотя бы одна проверка качества не пройдена.
Успешное открытие и преобразование файла само по себе не означает правильного
распознавания. Число должно находиться в нужной строке таблицы; для чека оно
также должно присутствовать в обычном текстовом результате.

Образцы не содержат проверки рукописи, подписей, QR-кодов и закрытых полей.
Два повреждённых значения позиций второго чека исключены до первого запуска.
НДС первого чека сравнивается с напечатанным значением, а не вычисляется заново.
Важные суммы по-прежнему нужно сверять с изображением.

Повторный просмотр исходного PDF выявил одну ошибку в первоначальной записи
образца: в строке `1180` третье число напечатано как `75 393`, а было записано
`76 393`. Исходный `references.json` сохранён без изменения байтов. Отдельный
`reference_adjudications.json` хранит поправку, страницу, контрольную сумму
источника и основание. Параметр `--use-source-review` применяет эту поправку;
отчёт также сохраняет результат по первоначальному образцу. Без этого параметра
проверяется только первоначальный образец. Остальные значения, области и пределы
ошибок остаются прежними.

Все четыре действительно ошибочных финансовых значения исправлены; пятое
расхождение оказалось ошибкой образца, описанной выше. Число `574 118` читается
по отдельной спорной цифре после проверки всей ячейки. Номера строк и ссылки
на примечания не обрабатываются как суммы. Готовый текст PDF сохраняется при
явном выборе обычного режима; дополнительное чтение чисел требует слов из OCR
в самой ячейке. Знаки, количество цифр и десятичные разряды проверяются до замены.

Печатный НДС первого чека теперь распознан как `15.64`. После дополнительного

и пропущенные знаки `=`. Оба участка совпали с первоначальным образцом
посимвольно. Все их строки и знаки сохранены в обычной текстовой выгрузке;
порядок блоков в ней определяется разметкой страницы. Контрольные участки двух
PDF сохранили ошибки в символах 0% и 1,66%; цветная фотография документа — 0,62%.
Все восемь прежних искусственных тестовых страниц также прошли проверку.

**Все условия качества прошли десять из десяти случаев** после документированной
сверки образца. По первоначальному образцу результат — девять из десяти;
оба результата сохранены. Файлы источников, первоначальные образцы, области,
исключения и пределы ошибок не менялись. Числа не подменялись расчётными значениями
или ответами из образцов. Это проверка разработки на небольшой известной выборке;
она не подтверждает безошибочную обработку других документов.
